# 사전 검토와 결정

독립 리뷰 1회와 작성자의 수정 후 검토를 수행했다. iOS 컴파일과 실기기 테스트는 수행하지 않았다.

| 발견 사항 | 반영한 수정 | 검증 범위 |
|---|---|---|
| nonescaping 클로저를 저장해 Swift 컴파일 오류 가능 | FileCoordinator에 리터럴 클로저 직접 전달 | 정적 검토/Swift 문법 파싱, 컴파일 미확인 |
| Pencil 최종 필압 콜백이 저장에서 빠질 수 있음 | drawingDidChange를 모델에 반영, stroke undo 그룹, 닫기 전 정착 대기 | 소스 검토, iPad 검증 대기 |
| 녹음 메타데이터 실패 시 원음 연결 복구 불가 | 녹음 시작 전 durable pending 기록, 재연결/보존 후 새 녹음 경로 | native 테스트 작성, 실행 대기 |
| 외부 버전 읽는 동안 새 편집이 버려짐 | revision 검사 및 다시 열기 중 편집 비활성화 | native 테스트 작성, 실행 대기 |
| 붙여넣기가 임의의 페이지로 감 | PDFView.currentPage에서 overlay 조회 | 소스 검토, iPad 검증 대기 |
| 빠른 폴더 이동 때 새 요청이 버려짐 | 단일 mutation guard와 최신 목록 요청 분리 | 회귀 테스트 실패 후 수정, 전체 JS 테스트 통과 |

추가로 iPad에서 기록한 입력 SHA256이 Windows의 입력 SHA256과 맞을 때만 AI 처리하도록 구현했다. 단순 파일 존재를 iCloud 동기화 완료의 증거로 쓰지 않는다. 해당 동작은 독립적인 JS 회귀 테스트로 확인했다.

## 결정과 남은 비용

- Editor 도구 막대와 PDF/Pencil 입력은 Swift에 둔다. Expo는 서재/수업/설정 화면을 담당한다. 따라서 서재 화면은 빠른 반영이 가능하지만 도구 막대와 필기 엔진 변경은 새 네이티브 빌드가 필요하다.
- 필기는 편집 원본 PKDrawing과 2배 이하 이미지 appearance로 같은 PDF에 저장한다. 원본 텍스트와 외부 주석은 유지하지만 앱 필기의 공개 저장 표현은 벡터가 아니다. 고배율/인쇄 품질 검증이 남는다.
- 이 PC에서는 Apple SDK가 없어 iOS 타입 검사·링크·권한·실기기 성능·Windows PDF 호환성을 확정할 수 없다. 13개 native 테스트를 작성했지만 실행하지 않았다.
- 최종 사용자 결정은 iCloud만 사용, 노트북/Codex를 켜두고 22시 로컬 자동 처리, 별도 유료 API 없음이다. Google Drive 전송과 클라우드 우회는 구현/실행하지 않았다. 예약 22는 다시 ACTIVE로 설정했다.
- 이번에 레퍼런스 영상을 다시 재생하지 않았다. 플렉슬과 같은 모든 조작/필압/제스처 동등성을 주장하지 않는다.
- 의존성 감사에는 23개 항목(높음16/중간7)이 남는다. Expo 도구 체인의 braces, node-forge, uuid 관련 전이 의존성이 포함된다. 호환성을 깨는 강제 구버전 변경은 하지 않았다. 배포/공개 개발 서버 운영 전에 다시 점검해야 한다.

원본 영상 재검토, 선택 핸들의 정교한 크기 조절, 자동 도형 인식, 벡터 잉크 export, 원문 Markdown 수식 조판은 추가 검증/개선 범위다. UI에 없는 기능을 완성됐다고 표시하지 않는다.
